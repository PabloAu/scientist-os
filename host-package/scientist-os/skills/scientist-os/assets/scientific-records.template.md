# Portable scientific record contracts

Copy only a relevant section into project state or translate it into the discovered Python operation schema. These are scientific content contracts, not additional records the scientist must manually fill out. `unknown` is an honest value; an empty field is not evidence that a gate passed.

## Inventory candidate / dataset

- Recognizable experiment date/label and exact permitted source locator; prior owner description and literal scope.
- Index/workbook row and detail-sheet links; active/review/deferred/excluded disposition, reason and actor.
- Stable dataset identity if retained; original scope, checksum/manifest status, modality and reader/version.
- Raw counts/bytes/times/errors/warnings, acquisition denominator, controls, experimental/statistical hierarchy.
- Material/protocol assignments: literal scope, record/version, deviation, evidence/precedence, applicability state.
- Derived roots and producer completion; two manifest observations with interval and identity comparison.
- Processed-data/analysis/output and downstream-use links; readiness state, missing gates and questions.

## Source, term and claim

- Source: ID, original/metadata-only status, origin/rights, hash/version, authority/publication class, extraction tool/quality, exact and visually inspected locators, corpus state.
- Term: concept, preferred term, field/project definitions, aliases, excluded meanings, operational limits, source coverage/conflicts, scoped approval.
- Claim: exact wording/version/type/scope, source/project evidence and locators, direct/partial/contextual/contradictory/unsupported relationship, permitted/prohibited inference, alternatives, approval owner/use/version.
- Every source's topic index, term disposition and evidence rows; gaps/acquisition status and re-entry trigger.

## Run record

- Purpose, hypothesis/estimand, plan/freeze, scientific decisions, exploratory/confirmatory status.
- Exact selected inputs, versions/hashes/locators and selection criteria; independent units/nesting and units.
- Repository/remote availability, immutable commit, dirty/patch status, module/command, configuration/hash/resolved defaults.
- Runtime/platform/dependency lock/environment hash, seeds, execution date/status/time/logs and failure evidence.
- Explicit run-level synthetic flag for simulations/fictional fixtures; actual actor/basis for fixture decisions, never fabricated human approval.
- Exclusions/missingness, QC, sensitivity/falsification, failure denominators and limitations.
- Exact output files/hashes and lineage to analysis, panels, claims, sections and slides; declared replay tolerances/results.
- For native figure registration: completed verified run ID, exact selected supported result JSON filename/hash and bound figure title; actual register-result output IDs.

## Decision and scoped approval

- Question, options, rationale, actual decision-maker and date.
- Exact source/record/artifact versions and purpose/claim/term/use scope.
- Corpus-use approval: actual scientist statement recorded with matching scope and source IDs; saved evidence fingerprint and approval-decision revision, current scope freshness.
- Scientific decision versus agent implementation choice versus tool permission.
- Conditions/limits, unresolved facts, superseded decision and re-entry trigger.

## Scientific writing report

- Selected artifact/revision and passage/panel/slide target; proposed change and actor.
- Claim-evidence/state/limits report; citation identity/fit/original-check report.
- Terminology/operational-meaning/conflict report; change rationale/affected artifacts/open questions.
- Cross-document facts reconciled; actual rendered file/hash, renderer, pages/slides checked and unresolved defects.

## Review round and atomic request

- Exact decision/report originals, deadline, submitted baseline manifest and current change history.
- Request ID, original reviewer number/order/quotation/locator, interpretation and ambiguity.
- Submitted/current targets, affected claim/risk, governed records and full-inventory evidence considered.
- Classification, options/tradeoffs, least-expansive adequate disposition, necessity/feasibility assessment if new work.
- Owner, dependent scientific decisions, status/validation, response paragraph and exact clean/marked locations.
- Current request evidence IDs and captured accepted revisions; stale-evidence findings and substantive reassessment before revision.
- Approved plan, clean/marked/response consistency, actual approvals and exact resubmission manifest/acknowledgement.

## Problem and verified improvement

- Problem ID/status, observed versus expected behavior, evidence, scope/stage/records and immediate containment.
- Cause/confidence, routine versus material classification, options/tradeoffs, owner/decision needs.
- Representative failure reproduction, fix and unaffected-case check, actual result and version.
- Existing-adequate/refine-existing/new-skill-candidate/material-decision; narrow owning procedure and applicability limits.
- Resolution or accepted limitation, monitoring/re-entry trigger and catalog/roadmap reconciliation.
